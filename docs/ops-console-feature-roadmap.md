# Ops Console 功能路线图（support / dev 视角）

日期：2026-10-29　分支：feature/v2.0.0

## 三条不可协商的设计前提

### 1. 严格按站点隔离

所有新增能力**只在当前 site 维度内聚合**，不做跨站点总览、不做跨站点对比。
数据键、接口路径、前端状态一律带 `site_id`；任何"全局视图"都不在本路线图范围内。

### 2. 权限降级优先（非 root 服务器）

被纳管服务器**不保证 root**。因此：

- **每个采集项独立降级**：一条命令因权限/不存在/超时失败，只让该项显示「不可用 + 原因」，
  不影响同页其它项，也不让整页变 Unknown。
- **启动探测 + 缓存**：每个 Server 首次采集时探测一次能力（是否 root、某路径是否可读、
  某命令是否存在），结果缓存（`ops:cap:{server_id}`，TTL 与资源缓存同量级），
  前端据此隐藏或标注不可用项，避免每次轮询都撞权限错误。
- **区分两种「没权限」**：
  - SSH 模块（用户自己敲命令）→ 原样回显 `Permission denied` 是正确的。
  - 系统功能（本路线图的采集项）→ **不能把权限错误抛给用户当故障**，
    要显示「该项需要额外权限，当前账号不可用」，且**不触发告警、不计入诊断**。
- **优先选择无权限要求的等价数据源**：例如 OOM 优先 `dmesg`，不可读时回退
  `/var/log/kern.log`、`/var/log/syslog`，都不可读则标记不可用。

### 3. 只读 + 白名单

采集命令全部是模块常量白名单，无用户输入拼接。唯一例外是日志查看器——
它的"文件路径"必须来自**站点配置里的白名单路径列表**，不接受任意路径。

## P0 / P1 逐项设计

### P0-1 失败的 systemd 单元

- 命令：`systemctl --failed --no-legend --plain`
- 权限：非 root 可执行；容器内可能无 systemd → 命令返回非 0 或空
- 解析：每行 `unit load active description` → `{unit, description}`
- 降级：命令失败 → `systemd: null`，前端显示「不可用（无 systemd 或无权限）」
- 展示：Server 页新增卡片，数量 >0 标红，点开看列表

### P0-2 OOM 击杀记录

- 命令（按顺序尝试，命中即止）：
  1. `dmesg -T 2>/dev/null | grep -iE 'out of memory|killed process' | tail -5`
  2. `/var/log/kern.log`（可读时）`tail -c 256K | grep -iE ... | tail -5`
  3. `/var/log/syslog`（可读时）同上
- 权限：`kernel.dmesg_restrict=1` 时 dmesg 需 root；日志文件常属 root/adm
- 解析：提取时间 + 进程名 + 内存占用
- 降级：三路都不可读 → `oom: null` + 原因「需要 root 或 adm 权限」，**不告警**
- 展示：Server 页卡片，最近一条 OOM 时间 + 进程名；无记录显示「无」

### P0-3 CPU steal time

- 来源：现有 `top -bn2` 的 CPU 行，新增解析 `st`（与 `id`/`wa` 同处）
- 权限：无要求
- 展示：CPU 卡副行追加 `steal X%`，≥5% 标黄（宿主机超卖信号）

### P0-4 运行时长 + 重启记录

- 来源：`uptime` 输出已含 `up X days, HH:MM`；另加 `who -b`（boot 时间）
- 解析：`uptime_text` 原始串 + `boot_time` ISO 串
- 降级：`who -b` 在容器内常为空 → 只用 uptime 串
- 展示：Server 页顶部信息条「已运行 37 天 4 小时」；重启（uptime < 上次记录）时写一条事件（P1-17 时间轴复用）

### P0-5 文件句柄使用率

- 命令：`cat /proc/sys/fs/file-nr`
- 解析：三列 `allocated unused max` → 使用率 `allocated / max`
- 权限：世界可读
- 展示：Server 页卡片或并入 CPU 副行；≥80% 黄、≥90% 红

### P0-6 一键巡检报告

- 数据：现有 `diagnosis` + 各资源最新状态 + 最近变更
- 形态：前端把当前站点快照渲染成**纯文本**（可复制），不做后端新接口
- 内容：站点名 / 生成时间 / 最严重级别 / 各资源状态与问题 / 最近 5 条变更
- 展示：Overview 页「复制巡检报告」按钮

### P0-7 配置变更 diff

- 后端：`oplog.record` 增 `before`/`after` 两个字段（仅存变更的键，不存全量密码）
- 敏感字段（`password`）一律存 `"***"`，不落明文
- 前端：Audit 页每条资源变更可展开看 diff（红删绿增）
- 降级：历史记录无 before/after → 显示「旧记录无差异信息」

### P0-8 Redis 深度指标

- 来源：现有 `INFO`（已调用），补充展示：
  `keyspace_hits/misses`（命中率）、`evicted_keys`、`rejected_connections`、
  `blocked_clients`、`connected_clients`、`mem_fragmentation_ratio`、
  `used_memory` / `maxmemory`、`instantaneous_ops_per_sec`
- 权限：网络访问，无 OS 权限问题
- 展示：Redis 页顶部指标条；`evicted>0` / `rejected>0` / 碎片率 >1.5 标黄

### P0-9 MQ 最老消息滞留时长

- 来源：Jolokia 队列属性 `FirstMessageAge`（毫秒）；不可用时回退 `LastMessageAge`
- 解析：换算为秒/分钟；与「消息数」并列
- 降级：属性不存在 → 显示 `-`
- 展示：MQ 队列表新增「最老消息」列；>5 分钟标黄、>30 分钟标红

### P1-10 PSI 压力指标

- 来源：`/proc/pressure/cpu`、`/proc/pressure/io`、`/proc/pressure/memory`
- 解析：`some avg10=X avg60=Y avg300=Z total=N` → 取 avg10
- 降级：内核 <4.20 或无文件 → `psi: null`，整卡隐藏（不显示"不可用"噪音）
- 展示：Server 页「系统压力」卡片，三条平均压力条

### P1-11 日志查看器（新模块 `logs`）

**不做全文件检索，只做字节窗口**——成本与文件大小无关。

- 白名单：日志路径来自站点配置（`logs` 资源类型，字段 `path` + `label`），不接受任意路径
- 命令（全部固定模板，路径来自白名单且做 shell 转义）：
  - 末尾：`tail -c 524288 <path> | tail -n 200`
  - 指定偏移向上：`tail -c +<offset> <path> | head -n 200`
  - 开头：`head -n 200 <path>`
  - 搜索：`tail -c 2097152 <path> | grep -n -i -- <kw> | head -n 100`
  - 跟随：前端 3s 轮询，带上次字节偏移，只取新增
- 前置检查：`test -r <path> && stat -c '%s %i' <path>` —— 不可读 → 明确提示「无读取权限」
- 轮转检测：inode 变化 → 重置到末尾并提示
- 权限：需对日志文件可读（常见属主 root/adm）→ 配置页提示「建议用 adm/sudo 组账号」
- 降级：任何一步失败只影响该次操作，页面保留已加载内容

### P1-12 依赖连通性矩阵（新模块 `netdiag`）

- 来源：后端对「站点内配置的 Server/Redis/MQ/Device 主机」做 TCP connect + 时延
- 权限：后端出站，不涉及目标机权限
- 降级：超时 3s，标「不可达」
- 展示：表格 目标 / 端口 / 结果 / 时延；可手动重测

### P1-13 磁盘写满预测

- 数据：现有采样里 `disk.use_percent` 序列
- 算法：对每个挂载点做最近 N 点线性回归，斜率 >0 时推算「距 100% 天数」
- 降级：样本 <10 点或斜率为负 → 不显示
- 展示：磁盘表新增「预计写满」列

### P1-14 设备接口响应耗时

- 来源：`device/provider` 每次 HTTP 调用计时
- 展示：Device 页实例信息条显示「响应 123ms」；>2s 标黄

### P1-15 字段映射失效检测

- 来源：最近一次响应 JSON + 实例 `field_map`
- 判定：映射里声明了但响应中取不到值（路径不存在）
- 展示：Device 页顶部提示「N 个字段映射失效：xxx」，点开看清单

### P1-16 配置卫生清单

- 数据：站点内所有资源的静态配置
- 检查项：Server 无阈值覆盖 / Device 无字段映射 / MQ 队列无消费者 / Redis 无密码 /
  Page 无 URL 且无 HTML / 资源长期无数据
- 展示：Overview 页「配置建议」卡片，纯静态、零采集

### P1-17 事件时间轴

- 存储：平台 Redis list `ops:events:{site_id}`（上限 200 条，LPUSH + LTRIM）
- 事件来源：诊断状态变化、服务器重启（uptime 回退）、配置变更（oplog）、
  连通性由通变不通
- 展示：Overview 页时间轴，倒序，带类型图标
- 降级：写事件失败不影响主流程（fire-and-forget）

### 并行纪律

- 每路 agent 只碰自己的模块目录 + 自己的测试文件；
- **i18n 文案由控制方统一追加**（agent 在报告里列出所需 key），避免多路并发改同一文件；
- 每路自带测试，合并前跑 `uv run pytest backend/tests -q` + `npx vitest run` 双绿。
