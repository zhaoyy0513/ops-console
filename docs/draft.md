需要实现一个内部使用的监控平台.
平台要求：
1. 后端使用python.13 fastapi +前端使用 vue+mui+pinia+typescript+es6+vite,+缓存用redis
2. 查询服务器的内容应该是通过python做连接然后 触发指令查询linux系统的部分指标，比如磁盘占用率，cpu使用率等，链接可能是域名也可能是直接IP只连
3. 通过api查询activemq的使用情况,使用的版本是artemis-2.19，会提供对应的链接信息
4. 通过ip直接链接redis，在redis对应的tab做操作
5. 可以通过勾选已有站点进行站点切换，所以要有一个站点维护功能，站点也就是不同服务器，可以配置的内容包括
    1. activemq的链接情况
    2. redis的配置信息，比如账号，密码，db号等，注意：可以配置空密码，因为很多站点默认是没有设置密码的 
    3. 后续待定 
6. 系统设计的时候需要注意缓存的设计，不要过于复杂，也不要大批量的轮询，长连接等等避免长期占用系统资源，设计的系统要简而美，性能高
而不失华丽感，页面设计的时候尽量不要AI感太重
7. 因为可能设计很多不同的tab，比如redis了，机器人了，mq了，系统了，所以可能做切换，所以这个切换功能你看下要怎么做，
尽量不要让用户输入很多次信息


监控的内容包括：
1. 比如调用robot接口查询机器人状态，也就是一个table表单可以查询机器人
2. redis信息查询，可以将所有db下不同的key列出来，然后可以进行增删改查，改和删要加alert提醒，
最好这种提醒带时间倒计时，类似于几秒后才可以点确定那种，防止用户点击过快
3. mq信息查询，比如默认进这个tab的时候显示mq的连接状态，占用率啊，cpu使用率这些
然后可以通过activemq提供的api查询信息，比如某个topic的连接数量，mq堆积个数，未消费个数什么的，你也可以想想还有哪些比较关键
4. 系统状态查询，实时的可以看到服务器的状态信息， 比如cpu使用率了，内存使用率了，磁盘使用率啊，然后你甚至可以总结一下当前的状态，比如memory above threshold了
什么的，然后看看是不是有什么逻辑比如阈值什么的，然后展示绿色红色状态什么的。
